# 🤖 AI Career Coach — Conversational Onboarding & Automatic Profile Intelligence

## Priority

P0 — Critical

## Objective

Make the AI Career Coach the FIRST experience a new user encounters after
successful signup/login.

Do NOT show the normal dashboard first.

For a new user:

Signup
↓
AI Career Coach
↓
Conversational onboarding
↓
Collect profile information
↓
Connect GitHub / LeetCode / LinkedIn / Resume
↓
Analyze available evidence
↓
Automatically build the user's profile
↓
Estimate skill levels
↓
Calculate initial Placement Readiness
↓
Show generated profile/report
↓
Enter the main GetPlaced dashboard

The onboarding should feel like talking to a personal AI placement coach,
NOT like filling out a long registration form.

# 6. DYNAMIC QUESTIONING

The AI must adapt its next question based on the user's previous answer.

Example:

AI:

"What technologies do you currently work with?"

User:

"Java and Spring Boot."

Do NOT ask:

"What programming languages do you know?"

Instead continue intelligently:

"Nice. Have you built any projects using Spring Boot?"

User:

"Yes, I built a REST API."

AI:

"Was it deployed anywhere?"

User:

"Yes, on Render."

AI:

"Great. I'll use that as evidence of production/deployment experience."

This should feel like an intelligent conversation.

---

# 7. DO NOT ASK FOR INFORMATION ALREADY DISCOVERED

If the user says:

"I have a GitHub with all my projects."

The AI should ask for the GitHub URL.

After GitHub analysis identifies:

Java
React
Spring Boot

Do NOT ask:

"What technologies do you know?"

Instead:

"I found Java, React and Spring Boot across your repositories. Are there
any technologies you use that aren't represented on GitHub?"

This reduces onboarding friction.

---

- Public repositories
- Repository count
- Relevant repositories
- Languages
- Technologies
- Repository activity
- README quality
- Project complexity
- Project completeness
- Deployment links
- Recent activity

Do not duplicate the existing GitHub analysis system.

# 9. LEETCODE COLLECTION

Ask:

"What's your LeetCode profile?"

User provides their username/profile URL.

Use the existing LeetCode integration where available.

Collect available public information:

- Total problems
- Easy
- Medium
- Hard
- Languages
- Submission activity
- Acceptance information where available
- Recent activity
- Contest/rating information where available
